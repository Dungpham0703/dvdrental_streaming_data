Summarize your technical report for a Data Engineer who is learning the system.

For every high-priority finding, explain:

1. The problem in plain language.
2. A small concrete example of how it fails.
3. The exact code evidence supporting the finding.
4. What has been proven by static inspection versus runtime testing.
5. The expected impact on data correctness, reliability, or cost.
6. The smallest safe next step.

Then list:
- Any assumptions that may be wrong.
- Any important edge cases you have not investigated.
- Any recommendations that are not yet supported by evidence.

Do not introduce new findings without identifying their evidence. Do not implement any changes.
